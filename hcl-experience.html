Data Architecture & DAX Measures

Behind the visual layer, the analytics engine relied on an automated Power Query ETL pipeline, a star schema relational data model, and custom DAX measures engineered to calculate dynamic utilization and risk thresholds on the fly.

Sample Custom DAX Formulations

// 1. Dynamic Workforce Utilization Rate Utilization % = DIVIDE( CALCULATE( COUNTROWS('Employees'), 'Employees'[BillableStatus] = "Billable" ), COUNTROWS('Employees'), 0 ) // 2. Dynamic Departmental Attrition Rate Attrition % = DIVIDE( CALCULATE( COUNTROWS('Employees'), 'Employees'[Attrition] = "Yes" ), COUNTROWS('Employees'), 0 ) // 3. Portfolio Project Risk Classification Projects At Risk = CALCULATE( DISTINCTCOUNT('Projects'[ProjectID]), 'Projects'[HealthStatus] = "At Risk" )

Power Query ETL & Star Schema

  • Data Ingestion & Cleansing: Imported messy employee tracking logs and transactional billing tables. Cleansed null values, standardized date formatting, and created unified employee surrogate keys using Power Query.
  • Star Schema Optimization: Structured a central fact table (Fact_WorkforceUtilization) linked through one-to-many relationships to five dimension tables (Dim_Employee, Dim_Project, Dim_Client, Dim_Department, and Dim_Date).
  • Interactive Slicer Synchronization: Configured cross-filtering across 6 global slicers (Year, Department, Country, JobRole, Project Name, Client Name) with bidirectional cross-filtering disabled to preserve sub-second query performance.
